# Резервное копирование OpsBrief (живой SQLite)

Выполняется на работающем VPS без остановки API. Источник — Docker volume
`opsbrief_opsbrief_data`, внутри которого `/data/opsbrief.sqlite3`.

## Выполнить один раз вручную

```bash
cd /opt/opsbrief
sudo bash infra/scripts/backup-sqlite.sh
sudo ls -lh /var/backups/opsbrief/
```

Скрипт использует локальный Docker-образ `opsbrief-api` в отдельном
одноразовом контейнере без сети. Файловая система источника монтируется
только для чтения; SQLite Backup API делает согласованную копию. Скрипт
проверяет `PRAGMA integrity_check` и таблицу `briefs`; неуспешная копия
удаляется. Архивы создаются с правами `0600` в каталоге `0700`.

Иные значения можно установить локальными переменными окружения
`OPSBRIEF_VOLUME`, `OPSBRIEF_BACKUP_IMAGE`, `OPSBRIEF_BACKUP_DIR`.

## Тест чтения резервной копии

```bash
sudo python3 -c 'import glob,sqlite3; f=sorted(glob.glob("/var/backups/opsbrief/*.sqlite3"))[-1]; c=sqlite3.connect("file:"+f+"?mode=ro",uri=True); print("file:",f,"integrity:",c.execute("PRAGMA integrity_check").fetchone()[0]); c.close()'
```

Не печатать содержимое таблицы `briefs`: там может находиться приватная сводка.

## Восстановление

Восстановление на рабочем томе пока намеренно **не автоматизировано**:
оно требует остановки приложения, дополнительного свежего бэкапа и
явного согласования, чтобы не потерять последние загруженные сводки.
На этой стадии проверяется только читаемость резервной копии.

Не хранить единственную копию на том же VPS. Следующая итерация —
зашифрованное внешнее хранилище, ротация и тест восстановления в
изолированный том.
